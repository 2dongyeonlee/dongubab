# perf-log — 성과 기록·계정 점검

## 모드
| 모드 | 트리거 | 산출 |
|---|---|---|
| 기록 | 게시물 1~N개의 수치·캡처 입력 | 성과기록 .xlsx에 행 추가 + `log/NNN-가게명.md` |
| 점검 | "최근 영상 점검", "계정 점검" | `log/YYYY-MM-DD_dongubab_계정점검.md` 리포트 |

## 입력 받는 법
- 인스타 인사이트 캡처 또는 수치 붙여넣기. 게시물마다 아래 필드를 받는다.
  게시일, 가게, 카테고리, 협찬여부, 커버 문구(이미지 글자), 조회, 도달(조회한 사람), 비팔로워 %, 좋아요, 댓글, 공유, 저장, 팔로우, 평균 시청(초), 건너뛰기율
- 캡처에서 읽은 값은 그대로 옮기고, 판독이 불확실한 숫자는 셀 대신 메모에 "확인 필요"로 남긴다. 값을 추정해서 채우지 않는다.
- 빈 지표는 빈칸으로 둔다(0으로 쓰지 않는다. 0은 실제 0일 때만).
- 카테고리·커버 유형 값은 `references/metrics.md`의 목록에서만 고른다.

## 기록 모드 절차
1. `log/` 안의 가장 최근 `*_성과기록*.xlsx`를 찾는다. 없으면 `scripts/make_perf_sheet.py`로 새로 만든다.
2. 기존 파일은 덮어쓰지 않는다. 행을 추가한 결과는 `_v2`, `_v3`로 저장한다.
3. 비율 열(공유율·저장율·팔로우율 등)은 수식을 복사한다. 값으로 계산해 넣지 않는다.
4. 게시물별 `log/NNN-가게명.md`를 기존 001·002 형식(커버/성과/캡션/구조 태그/교훈)으로 만든다.

## 점검 모드 절차
1. 최근 게시물 최소 8개 이상이 기록돼 있는지 확인한다. 미만이면 결론 대신 "표본 부족"으로 표기하고 경향만 쓴다.
2. 아래 순서로 리포트를 쓴다.
   1. 결론 3줄: 무엇이 팔로우를 만들었나 / 무엇이 조회만 만들었나 / 다음 4편에 바꿀 것 1가지
   2. 상·하위 3개 비교표(커버 문구, 커버 유형, 카테고리, 공유율, 팔로우율, 평균 시청)
   3. 카테고리별·커버 유형별 평균(요약 시트 수치 인용)
   4. 정체성 진단: 팔로우율 상위 게시물의 공통점. 이게 "내꺼" 후보다.
   5. 차용할 형식 vs 지킬 정체성 표: 형식(훅 구조, 줄 수, 컷 호흡)은 차용 후보, 소재·톤·시선은 정체성
3. 해석은 "추정"으로, 수치는 시트 값만 쓴다. 다른 계정 수치를 기준선으로 쓰지 않는다.

## 판단 원칙 (수치 기준선 없음, 원칙만)
- 먼저 노출을 본다: 조회와 **비팔로워 비율**. 비팔로워가 낮으면(팔로워 안에서만 소비) 전환 지표보다 노출 문제로 진단한다.
- 그다음 지표 우선순위: 공유/조회 > 팔로우/조회 > 저장/조회 > 평균 시청. 좋아요·댓글은 참고만(협찬 이벤트 댓글 착시).
- 평균보다 **중앙값**을 쓴다. 히트작 1~2개가 평균을 왜곡한다.
- 조회가 높은데 팔로우율이 낮으면 "바이럴이지만 계정 성장 없음"으로 분류한다.
- 공유 ≥ 저장이면 소환형, 저장 > 공유면 위시리스트형으로 태그한다.
- 협찬과 비협찬은 분리해서 비교한다(협찬은 소재 선택권이 없으므로).
- 알고리즘 관련 외부 수치는 블로그 2차 해석이라 규칙에 넣지 않는다(확인 필요).

## 하지 않는 것
- 인스타그램 스크래핑·외부 API 호출(Apify 등)은 하지 않는다. 자동 수집은 [검토중]이며 보안·법무 검토가 필요하다.
- 기존 xlsx·md를 덮어쓰지 않는다.
